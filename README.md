## 🏗️ Software & Platform Engineering

I work across the full engineering lifecycle, from product and domain architecture through application development, infrastructure, deployment, troubleshooting and production readiness.

The architecture behind Zunde follows several core principles:

- Controllers orchestrate; services own business rules
- Repositories own data access
- Models own persistence
- Routes contain no business logic
- Applications maintain clear domain ownership
- Shared capabilities belong in governed shared packages
- Permissions and security controls are centralised
- UI and design capabilities are reusable across products
- Production changes are validated and evidence-driven
- Architecture validation is part of the engineering lifecycle

This allows individual Zunde applications to remain domain-focused while participating in a wider enterprise platform.

## 🔍 Zunde Inspector

I'm also building **Zunde Inspector**, the engineering and governance control plane for the Zunde ecosystem.

Inspector is designed to understand the applications that make up Zunde and evaluate areas including:

**Architecture health • APIs • routes • controllers • services • repositories • models • permissions • dependencies • shared components • duplication • technical debt • platform standards**

Rather than relying solely on manual code review, Inspector helps turn engineering standards into **detectable and measurable rules**.

My engineering workflow increasingly follows:

**Discover → Assess → Remediate → Rescan → Validate → Certify**

This creates a foundation for increasingly automated and AI-assisted software engineering.

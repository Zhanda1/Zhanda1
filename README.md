**Zunde Technologies** is being built as an interconnected enterprise ecosystem rather than a collection of isolated applications.

## 🏗️ How I Build

I care strongly about **enterprise architecture, domain ownership, maintainability and engineering discipline**.

Some of the principles behind Zunde include:

* Controllers orchestrate; services own business rules
* Repositories own data access
* Models own persistence
* Clear domain boundaries between applications
* Shared capabilities belong in shared platform packages
* Centralised permissions and security controls
* Reusable design systems and UI components
* Evidence-driven compliance and governance
* Architecture validation as part of the development lifecycle

I'm also developing **Zunde Inspector**, an engineering control tower that analyses the Zunde codebase for architecture health, security, permissions, APIs, routes, services, repositories, models, duplicate components, technical debt and compliance with platform standards.
